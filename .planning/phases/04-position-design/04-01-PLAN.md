<objective>
Land the entire font-loading swap as one atomic, independently verified change: source the Source
Sans 3 variable WOFF2, self-host it, declare it, preload it, point `--vp-font-family-base` at it, and
stop VitePress's default theme from bundling its own Inter family.

Purpose: this is the phase's tracer. It is the one change with a real failure mode if split across
commits — deleting the third-party font import before the replacement declaration lands leaves every
page with no declared typeface and no build-time warning. It also proves the full delivery path
(static asset -> build config -> theme entry point -> CSS custom property -> rendered glyphs) end to
end before any of the nine downstream plans depend on that path existing. Nothing else in Phase 4
touches this path.

Output: a self-hosted variable font, a working `@font-face`/preload/`--vp-font-family-base` triad,
and a build that no longer ships ~670KB of unused font data.
</objective>

Do all six sub-changes in one commit. Do not commit any subset.

1. Create `docs/public/fonts/`. Source the font by running `npm pack @fontsource-variable/source-sans-3` in a scratch directory, extracting the tarball, and copying `package/files/source-sans-3-latin-wght-normal.woff2` to `docs/public/fonts/source-sans-3-variable.woff2`. Delete the tarball and the extracted `package/` scaffold afterwards. Do NOT run `npm install` or `npm add` for this package — it must never appear in `package.json` or `package-lock.json`. Confirm the copied file is 28740 bytes before continuing; if the byte count differs, stop and report rather than proceeding with an unverified binary.

2. In `custom.css`, delete the render-blocking Google Fonts `@import` rule that currently sits on line 7 under the `Typography Import` banner. Delete the whole rule, do not comment it out (project convention: delete dead code). Rename that section banner to `Typeface` using the existing 20-equals-sign banner convention, and put the `@font-face` block there instead, copied verbatim from 04-UI-SPEC.md § "Typeface & Loading Contract" step 2 — `font-family: 'Source Sans 3'`, `src: url('/fonts/source-sans-3-variable.woff2') format('woff2-variations')`, `font-weight: 200 900`, `font-style: normal`, `font-display: swap`. The `200 900` range is verified against the actual variable axis of this exact file; do not narrow it.

3. In `custom.css`'s first `:root` block, add `--vp-font-family-base` set to `'Source Sans 3', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`. Add it as a plain declaration with no `!important` — this is a variable override, which wins by plain cascade order in this codebase (the existing `--vp-c-brand-1` override is the proof). Do not add a `.dark` counterpart. Do not reorder or reformat the existing `--vp-c-brand-1` declaration or move it out of the first `:root` block: `assertBrandInSync()` in `config.js` parses that block with a regex at build time and will fail the build if its shape changes.

4. In `custom.css`, delete the entire bare `html { font-family: ...; -webkit-font-smoothing: ...; ... }` rule at lines 93-99 under the `Global Styles` banner — but preserve the three non-font declarations it carries (`-webkit-font-smoothing: antialiased`, `-moz-osx-font-smoothing: grayscale`, `text-rendering: optimizeLegibility`) by keeping the `html` rule and removing only its `font-family` declaration. The typeface must be declared exactly once, via the custom property in step 3.

5. In `config.js`, add one tuple to the `head` array, positioned after the existing favicon/RSS `link` entries and before the first `meta` entry so the preload appears early in `<head>`: tag `link`, attrs `rel: "preload"`, `href: "/fonts/source-sans-3-variable.woff2"`, `as: "font"`, `type: "font/woff2"`, `crossorigin: ""`. The empty-string `crossorigin` value is required, not a placeholder — it serialises to the anonymous-mode CORS attribute the later font fetch needs in order to reuse the preloaded response. Leave `workbox.globPatterns` alone; it already globs `woff2` and will now match the new file.

6. In `theme/index.js`, change the `DefaultTheme` import's module specifier to `vitepress/theme-without-fonts`. This is VitePress's own documented entry point for a site replacing the default typeface; without it the build keeps emitting and precaching fourteen unused default-theme font files regardless of what `--vp-font-family-base` says. Change nothing else in this file in this plan.

Then run a clean build and confirm the emitted assets.
