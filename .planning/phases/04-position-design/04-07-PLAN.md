  <action>
Remove every colour literal from the page's script block, applying UI-SPEC's three cases in order.

Case one, which covers the large majority: for any item whose colour is merely sequential or
categorical — segment mixes, competency breakdowns, cost-of-capital component bars, peer comparison
series, and every metric tile whose colour means nothing more than "brand emphasis" — delete the
colour or accent key from the item entirely. Every affected component already falls back to its
sequential palette entry when no colour is given, and that fallback is theme-reactive, proven in
Phase 3. This is a markdown-only edit requiring no component change. The reference to match is the
global-equity page's own metrics array, which already omits the accent key.

This includes the neutral greys used for baseline or comparison series. They are categorical, not
semantic, so case one applies: delete the key. The consequence is real and should be recorded in the
SUMMARY — a baseline series that reads grey today will take a palette hue instead. That hue
re-themes, which the grey literal does not, and no token exists for a recessive chart neutral.

Case two, which is narrow: an item whose colour carries fixed meaning regardless of its position in a
sequence keeps a colour key, but its value becomes a semantic name rather than a hex. On this page
that is the overvaluation marker set — the market-implied growth and market-implied cost-of-capital
bars, and any element signalling an unfavourable finding — which take the negative semantic name that
plan 04-06 taught the chart components to resolve. Any element signalling a favourable finding takes
the positive name. The market-price Snapshot tile is a special case: `HeroMetrics` applies its accent
as a CSS custom property rather than passing it to a canvas, so that one takes a `var()` reference to
the negative colour token directly.

Case three is a constraint, not an action: a CSS variable string cannot be given to a chart item
colour, because canvas rendering does not resolve `var()`. That is why case two resolves inside the
component rather than in markdown. Do not write a `var()` reference into any chart data array.

The football-field exhibit's market line needs no markdown change — plan 04-06 fixed it inside the
component.

Then run the number-formatting audit. This is exhaustive, not a spot check. Enumerate every numeric
value the page renders — Snapshot tile values, table cells, chart data labels, axis tick values, and
figures written into prose — and confirm each matches its type's rule: percentages to one decimal
place; per-share currency to two; aggregate currency in billions or millions to one decimal with its
unit suffix; firm counts, coefficients and ratio-style metrics as whole numbers or as the source model
reports them, with no forced decimal padding; and a thousands separator on every integer of four
digits or more. This page is already among the most rigorous on the site, so expect few changes —
but produce the enumeration, because the audit is the deliverable, not the diff.

Finally, confirm the exhibit set carries information rather than decoration: check that every one of
the thirteen subtitles states what a reader should take from the exhibit, not merely what the exhibit
shows. Every subtitle on this page is non-empty today; the check is whether each states a takeaway. If
any is purely descriptive, rewrite it to state the finding.
  </action>
