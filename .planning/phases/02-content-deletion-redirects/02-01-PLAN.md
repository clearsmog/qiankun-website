<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor → Cloudflare Pages edge | Untrusted request paths are matched against `_redirects` rules before any static asset lookup. |
| repository → build output → public CDN | Developer-authored content crosses into a publicly indexed artifact; anything left in `dist/` is world-readable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `docs/public/_redirects` destinations | low | mitigate | All six destinations are hardcoded internal paths (`/` and `/blog/`), never interpolated from a request. No `:splat` or `:placeholder` token appears in any destination field, so no attacker-supplied path segment can steer a redirect off-site. Acceptance criteria assert every rule line ends in `301` and the file has exactly six rules. |
| T-02-02 | Information Disclosure | `docs/.vitepress/dist/` | medium | mitigate | A deleted page whose built HTML survives in `dist/` stays publicly fetchable and crawlable despite appearing removed. Each task asserts the corresponding `dist/` route directory is absent after the build; sitemap and RSS regenerate from the on-disk page list every build, so no stale entry can persist. |
| T-02-03 | Information Disclosure | `docs/public/_redirects` (publicly fetchable) | low | accept | The rule file is served at the origin root and enumerates the retired URLs. All four groups were public pages with no confidential content, so disclosing that they existed reveals nothing not already indexed. |
| T-02-04 | Tampering | npm/pip/cargo installs | n/a | accept | This phase installs no packages — RESEARCH.md's Package Legitimacy Audit records "not applicable, no new packages". No install task exists in this plan, so no legitimacy checkpoint is required. |
</threat_model>
