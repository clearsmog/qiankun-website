<objective>
Prove both halves of this phase end-to-end on one thin path before scaling either: create the
Node-side token module, wire the PWA manifest through it, and convert exactly one chart component's
theme trigger from a `MutationObserver` to `watch(isDark, ..., { flush: 'post' })` — then verify the
whole path in a real browser.

Purpose: this phase has one silent failure mode. A converted watcher without `{ flush: 'post' }`
reads stale CSS custom properties on every toggle (RESEARCH.md traces this through Vue's scheduler
source at `runtime-core.cjs.js:424` — a default `flush: 'pre'` watcher is *structurally guaranteed*
to run before VitePress's class-flip watcher). That bug passes the build, passes every grep, and
renders a working-looking page. Proving the recipe on one component in a browser before applying it
to eleven more is the difference between one bad commit and twelve.

The single-source-of-truth end state is deliberately two cross-referenced literals, not one: CSS
cannot export a value to Node, and CONTEXT.md locks `--vp-c-brand-1` in `custom.css` as canonical for
anything the browser renders. `tokens.js` exists solely because the PWA manifest is generated in Node
before any DOM or stylesheet exists. Reciprocal comments make that boundary explicit rather than
silent — which is exactly what CONTEXT.md's discretion clause requires ("one canonical definition
plus explicitly-justified fallbacks — a silent duplicate is not").

This plan is visually neutral. Every change is an indirection change. A visible difference of any
kind is a defect, not an improvement.

Output: `docs/.vitepress/theme/tokens.js` (new, exporting `brand`), a `config.js` that imports it,
reciprocal sync comments in `custom.css` and `tokens.js`, and one converted chart component whose
correctness has been observed in a browser.
</objective>

<interface_context>
The conversion recipe established here is applied verbatim to eleven more components in plan 03-02.
Three reaction shapes exist across the twelve; this plan proves the first and most common.

**Shape A — "tick nudge" (10 components: EBar, EDonut, ELine, ECombo, EForest, EFootball, EGroupBar,
EHeatmap, EHistogram, EScorePath).** A `tick` ref is incremented to invalidate a `computed` that calls
`themeTokens()`. Current shape: `const tick = ref(0)`, a module-scope `let obs`, an `onMounted`
containing `obs = new MutationObserver(() => { tick.value++ })` plus `obs.observe(document.documentElement,
{ attributes: true, attributeFilter: ['class'] })`, and `onBeforeUnmount(() => obs?.disconnect())`.
Target shape: keep `const tick = ref(0)`; delete `let obs`, the whole `onMounted` block, and the
`onBeforeUnmount` line; add `watch(isDark, () => { tick.value++ }, { flush: 'post' })` with
`const { isDark } = useData()` above it.

**Shape B — `resize()` (VizEChart only).** Reaction is `chartRef.value?.resize?.()`. Plan 03-02.

**Shape C — `build()` (ProjectChart only).** Reaction is `build()`; `onMounted` also calls `build()`
and must survive; the nested `onBeforeUnmount` holding `chart?.destroy()` must survive as a top-level
hook. Plan 03-02.

**Import surface after conversion (Shape A):** `import { computed, ref, watch } from 'vue'` and
`import { useData } from 'vitepress'`. `onMounted` and `onBeforeUnmount` come out of the vue import —
the observer was their only consumer in all ten Shape-A files (verified: each file's `onMounted` body
contains nothing but the observer construction and `observe` call).

**`tokens.js` export surface:** one named export, `brand`. Consumed by `config.js` in plan 03-01 and
by `echarts-setup.js`, `ProjectChart.vue`, and `EHistogram.vue` in plan 03-02. No default export, no
dark-mode export — the dark value has zero JavaScript consumers and lives only in `custom.css`.
