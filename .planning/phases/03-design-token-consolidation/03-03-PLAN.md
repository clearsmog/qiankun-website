<objective>
Close this phase with the two verifications no grep and no build can perform: that twelve converted
charts actually recolour correctly in a browser, and that every gate holds against committed state
rather than a working tree.

Purpose: the phase's success criteria 3 and 4 are stated in terms a build cannot observe. "Charts
still re-theme correctly on toggle" and "no duplicate re-renders or console warnings" are browser
facts. Plan 03-01 proved the recipe on one component before scaling; this plan proves it on all
twelve, across the eight distinct ECharts component types that appear together on
`/projects/cisco-equity-valuation`. A stale-colour read is a per-component bug — one file missing its
post-flush option produces exactly one misbehaving chart on a page of eight, which is why the sweep
covers every type rather than sampling one.

The audit half re-runs every gate from plans 03-01 and 03-02 against a clean `git archive HEAD`
extract. Phase 2 established this precedent for good reason: an uncommitted edit that makes the
working tree pass and the deployed build fail is invisible to a working-tree check.

No file changes. Two verification tasks whose gates either pass or identify precisely what was
missed.
</objective>
